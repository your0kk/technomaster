# ТехноМастер 

Ремонт бытовой техники в Коченёво и Новосибирской области

## Запуск

Нужен Node.js 22+ (проверено на 24). Установленные версии: Next.js 16.3.6, React 19.3.0, TypeScript 5, Supabase JS 2.117.2. Точные версии зависимостей зафиксированы в `package-lock.json`.

```powershell
npm ci
# Только если .env.local ещё не существует:
Copy-Item .env.example .env.local
# Заполните три переменные по supabase/README.md
npm run dev
```

Откройте http://127.0.0.1:3000. Сервер по умолчанию привязан только к loopback
Для проверки production-сборки: `npm run build`, затем `npm start`.

Без публичных переменных каталог явно показывает учебные примеры. При ошибке подключённой БД отображается сообщение об ошибке, а не подмена её локальными данными. Отправка заявки без закрытого серверного ключа возвращает 503 и не показывает ложного успеха

## База и вход

Схема и учебные данные находятся в `supabase/migrations/202609270001_technomaster.sql`. Порядок применения через SQL Editor и получение ключей - [supabase/README.md](supabase/README.md). ER-диаграмма — [docs/er-diagram.md](docs/er-diagram.md).

Создайте учебный вход администратора командой `node --env-file=.env.local scripts/setup-admin.mjs`. Реквизиты находятся в локальном `.admin-credentials.local.json`, исключённом из Git. Затем войдите на `/admin`. Подробности и ручная альтернатива — в инструкции Supabase.

## Страницы и сценарий

| Путь | Назначение |
|---|---|
| `/` | Главная, услуги и популярные запчасти |
| `/services` | Услуги из БД и ориентировочный прайс |
| `/parts` | Каталог из БД, поиск по названию/артикулу/категории, фильтр категории |
| `/parts/[id]` | Деталь, наличие, цена и совместимость |
| `/request` | Форма вызова, прогресс, валидация, резюме |
| `/request/success?id=…` | UUID сохранённой заявки и статус «Новая» |
| `/admin` | Вход сотрудника, защищённый список, фильтр статуса, обновление |

Форма -> POST `/api/repair-requests` → валидация на сервере -> проверка активной услуги -> INSERT в Supabase -> возврат UUID и `new` → подтверждение в браузере. Экран успеха требует квитанцию, сохранённую после ответа 201 в sessionStorage текущего браузера; произвольный UUID в адресной строке не выдаётся за успешную отправку. В другом браузере подтверждение недоступно. Это квитанция отправки, не публичный сервис отслеживания.

Администратор входит через Supabase Auth; браузер передаёт access token в `/api/admin/requests`, сервер проверяет пользователя и его роль. Пароль и service role key не попадают в клиентский код. Токен не сохраняется между перезагрузками страницы; при истечении сессии нужно войти снова. Административная страница показывает последние 100 записей; после создания заявки нажмите «Обновить».

Форма гостя сохраняет тип, марку и модель прямо в заявке. `client_id` и `appliance_id` необязательны до регистрации. Отдельный справочник `appliances` сохраняет реляционную модель для зарегистрированных клиентов.

## Структура

```text
src/app/                 страницы App Router и API Route Handlers
src/components/          форма, карточки, административный интерфейс
src/lib/                 типы, данные примеров, валидация
src/lib/supabase/        отдельные браузерный и серверный клиенты
public/images/           фотографии из существующего прототипа
supabase/migrations/     схема, защита доступа, seed
supabase/verify.sql       запросы для проверки и отчёта
scripts/setup-admin.mjs   создание учебного входа
tests/                   проверки валидации и реляционной схемы
docs/                    ER-модель, сценарии, инструкция к отчёту
.github/workflows/ci.yml  npm ci → lint → tests → build
```

## Проверки

```powershell
npm run lint
npm test
npm run build
```

SQL-тест запускает ту же миграцию на PostgreSQL-движке PGlite с минимальными служебными объектами Supabase Auth. Он проверяет ограничения, FK, триггер и RLS. Это не эмуляция всего Supabase: работу REST API и Auth нужно проверять отдельно на подключённом учебном проекте. GitHub Actions готов к будущему использованию, но удалённый репозиторий и push в этом этапе не выполняются.

## Границы этапа
Работают создание и просмотр заявок, чтение каталога и вход администратора. Нет корзины и создания заказа, назначения мастера, изменения статуса из интерфейса, Telegram, оплаты и чеков
