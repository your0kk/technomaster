# Что показать в отчёте

Замечания преподавателя к предыдущей работе: недочёты оформления по ГОСТ, отсутствие изображений в таблице аналогов, недостаточно прецедентов. Они относятся к следующим отчётам; старый отчёт не изменяется. Конкретный ГОСТ и шаблон титульного листа нужно брать из методических указаний учебного заведения, а не заявлять соответствие произвольному стандарту.

## Последовательность скриншотов

1. **ER-диаграмма.** Откройте `docs/er-diagram.md` в просмотрщике Markdown с Mermaid. Сделайте общий снимок всех семи таблиц с читаемыми PK/FK и связями. При необходимости разместите диаграмму на альбомной странице. Подпись: «Рисунок 1 — Реляционная модель базы данных „ТехноМастер“».
2. **Таблицы Supabase.** В Dashboard проекта `technomaster` откройте Table Editor. Покажите список семи таблиц, затем отдельно поля `repair_requests` и `order_items`. Не фотографируйте экран API Keys или настройки с секретами.
3. **Главная страница.** Запустите приложение, откройте `/`, установите ширину окна около 1440 px. В кадре должны быть название, регион, основной призыв и услуги.
4. **Форма заявки.** Откройте `/request`, заполните вымышленным клиентом: «Учебный клиент», +7 (900) 000-00-00, Коченёво, ул. Примерная, 12. Введите технику, неисправность, будущую дату, время и согласие. Снимите поля и резюме до отправки. Используйте только учебные контакты.
5. **Подтверждение.** Отправьте форму. Снимите полный UUID и статус «Новая». Запишите UUID для следующего шага.
6. **Запись в БД.** В Table Editor → `repair_requests` отфильтруйте `id` по UUID с экрана подтверждения. Покажите совпадающие имя, технику, дату и статус. Это доказывает фактическую запись в реляционную БД.
7. **Каталог.** Откройте `/parts`, снимите фотографии, цены и наличие. Затем найдите `ASK-M231XP` и покажите результат поиска; откройте карточку детали.
8. **Административный список.** На `/admin` войдите с учебными реквизитами из `.admin-credentials.local.json`. Нажмите «Обновить», найдите заявку по первым 8 символам UUID, покажите статус «Новая». На скриншоте должен быть список, а не пароль или файл с реквизитами.
9. **Код и проверки.** Покажите POST-обработчик, таблицу `repair_requests` в миграции и успешные `npm run lint`, `npm test`, `npm run build`. При желании добавьте результат `supabase/verify.sql` с RLS и индексами.

## Как учесть замечания

- Таблица аналогов должна содержать реальные скриншоты каждого рассматриваемого сайта, подписи, ссылку и дату просмотра. Изображения нашего каталога не заменяют скриншоты аналогов. Не растягивайте иллюстрации непропорционально.
- Нумеруйте рисунки и таблицы последовательно, ссылайтесь на них в тексте до или рядом с размещением. Проверяйте переносы строк/таблиц, поля, отступы, шрифт и межстрочный интервал по вашей методичке. Не допускайте нечитаемых уменьшенных диаграмм.
- Для прецедентов используйте `docs/use-cases.md`: различайте реализованные сценарии текущего этапа и планируемые. Не представляйте Telegram и оплату как уже работающие.
- После экспорта отчёта в PDF визуально проверьте каждую страницу: подписи рядом с рисунками, отсутствие обрезанного текста и пустых случайных страниц.
